# REG-27: the long-watch replication

*Registered 2026-11-17 · GPU runs · claim C1 · result 2026-11-20*

| | |
|---|---|
| **Question** | Does REG-24's `confirms` (stuck through a 4500 s watch after the burst, drained in a long drop to λ = 1, recovered at the return to λ = 2.0) replicate on four more seeds? |
| **Runs** | 8 runs, ≈ 36 GPU h: per seed 61, 68, 72, 79, a long no-burst control and a burst run on the same session schedule, REG-24's design with only the seed changed (L1, 350 W, closed-loop turns; λ = 2.0 burst config with a 4500 s watch, λ = 1 for 9000 s, back to 2.0 for 1500 s; 16080 s of arrivals). Configs `configs/confirm_l1pl350cl_r2.0_s<seed>.yaml`, `configs/stage2_control_l1pl350cl_r2.0_long_s<seed>.yaml`. Seeds by a rule fixed before scanning: the first four in seed order (43 left out) whose burst schedule passes REG-24's W, E and F admission rules at a 9000 s drop. |
| **Outcome rule** | `reg27.classed`, `reg27.count`, `reg27.outcome` on `confirm.table(seed)`. A seed counts only beside a `control_warm` control. k = `confirms`; n = k + `not_persistent`, `reformed`, `emptied_in_watch`, `stuck_not_cold`, `no_return`. Not counted, reported beside k of n: `control_not_warm`, `control_missing`, `burst_missing`, `bad_baseline`, `inconclusive`, `not_same_build`, `drop_inconclusive`. Outcome: `too_few` (n < 3); `replicates` (k = n); `mixed` (0 < k < n); `does_not_replicate` (k = 0). One-sided 95 % Clopper–Pearson bounds both ways. |
| **Prediction** | Per seed: `confirms` ≈ 0.6 (`control_warm` ≈ 0.85 × ≈ 0.7 given a warm control and a valid burst run), a counted failure ≈ 0.25, not counted ≈ 0.15. Over four seeds: `replicates` 0.26, `mixed` 0.62, `too_few` 0.11, `does_not_replicate` 0.013. |
| **Decision under each outcome** | `replicates`: C1's sentence reads 'in k of k further seeds' with its lower bound (3 of 3: 0.368; 4 of 4: 0.473), seed 43 named apart. `mixed`: 'in k of n further seeds', each failure named by its label. `does_not_replicate`: seed 43 reported as the exception; conditions 5–6 not met at this cell. `too_few`: reported, no rerun beyond the stopping rule. Any surge flag: stop and rethink; K4's claim card gains the case. No outcome starts another run. |
| **Adversarial review** | One round before registration: three blocking items (uneven counting behind a non-warm control; a sealed folder read as missing; `drop_inconclusive` counted) and twelve advisories; the three blockers were fixed in the registered text and code. |
| **Result** | `replicates`: k = 4 `confirms` of n = 4 (seeds 61, 68, 72, 79), nothing not counted; one-sided 95 % bounds 0.473 to 1.000. Every control `control_warm`, no surge flag (the controls' highest 120 s planned peaks 2.725, 2.967, 3.000, 2.817). Each burst run stuck through the 4500 s watch; its total line drained 2560 / 2400 / 2830 / 2950 s into the 9000 s drop; the return's end (15480–16080 s) recovered. |
| **Prediction held** | no (`replicates` had 0.26 against `mixed` at 0.62) |
| **Not separated** | Persistence held by the clients' owed backlog against the pool size, rather than by C2's loop, is not separated (1532–1970 turns owed at the watch's end); the result does not test C2's chain. |
| **In the paper** | Appendix A, 'the long-watch replication'; §4.3 (P53; the order readout P54; Figure 1, P61); the controls in §4.1 (P43); the long-watch rows of Table 2 in §4 (P58); the drain row of the Appendix D table (P32). |
| **Notes** | The drop is 9000 s against PROTOCOL.md's 1800 s, by the author's ruling for REG-24. Unlike REG-24, each burst run followed its control in the queue unread. Burst run b68's attempt 1 was lost when the host was powered off and was rerun as attempt 2 under the registered rerun rule. Readouts: drain inside K3's band in 4 of 4; C1's order line `does_not_follow` in 4 of 4 (a readout here, so C1 still lacks condition 4's order clause); pooled with seed 43, 5 of 5 (biased upward, kept out of the C1 sentence). |
