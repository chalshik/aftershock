| **Question** | What does the saturated L1 server complete per second with caching off when turns are closed-loop? A measurement of the 8-turn closed-loop cold floor, so that 1.681 req/s is named the open-loop floor only and closed-loop margins are stated against a closed-loop floor. |
| **Runs** | One closed-loop cache-off sweep, `configs/sweep_l1pl350cl_pc_off.yaml` (REG-8's sweep with closed-loop turns and `loadgen_force_close`), seed 0, 900 s per rate, rates 1.5, 2, 2.5, 3, 3.5, 4. Six runs, one invocation, all valid on attempt 1. |
| **Outcome rule** | `e1.floor`: `gate.cold_floor` with REG-8's settings (mean KV ≥ 0.85, at least 2 runs, throughput < 0.95 × planned rate) → "ok". Only if that returns "not_monotone", the fallback `e1.floor_tail` → "tail_ok", "tail_too_few" or "tail_unsaturated". A swept rate without a valid run at or above λ_sat gives "holes"; no rows gives "no_rows". A floor exists only with "ok" or "tail_ok", labelled single seed (seed 0), one run per rate. |
| **Prediction** | P(status "ok") ≈ 0.75; P("tail_ok") ≈ 0.2; floor 1.70 to 1.80 req/s. Validity record: P(clean) ≈ 0.7; P(not clean) ≈ 0.3. |
| **Decision under each outcome** | A floor: the paper and `docs/model.md` may quote it as the closed-loop cold floor at 8 turns, with status, n, rates and the slope of throughput on rate; closed-loop margins are restated against it (each edit its own decision). No floor: K2's 8-turn closed-loop floor reported as unmeasured; E0's gate reads "missing". The floor sizes no run other than through E0's gate; a `recorder` or `gpu_steady` failure would stop every registration on this harness until its cause is recorded. |
| **Adversarial review** | Three rounds on drafts 5 to 7 (NOT READY, NOT READY, then READY provided DE1–DE7 were applied verbatim), after an earlier review of draft 3, with separate approval passes. All items were applied before the runs, one sentence of DE3 reworded to settle a contradiction. |
| **Result** | The 8-turn closed-loop cold floor is 1.798 req/s: status "ok", λ_sat 2.5, n 4, rates 2.5, 3.0, 3.5, 4.0 (seed 0, one run per rate). Throughput on rate over those rates +0.084 req/s per req/s (SE 0.019). E1's own 2.0 row completed 1.706 req/s at mean KV 0.755, below the rule's 0.85, and is not in the floor. |
