# P8192: the 8192 burst test

*Registered 2026-11-21 · GPU runs · claim P0 · result 2026-11-22*

| | |
|---|---|
| **Question** | Does REG-19's burst test leave the engine stuck at vLLM's 8192-token step budget, at a load inside that budget's window (λ = 2.2)? |
| **Runs** | 10 runs, ≈ 11.3 GPU h: control then burst run for each of five calm-schedule seeds 1002, 1004, 1007, 1008, 1009 (by a rule fixed before any schedule was computed: the first five unused seeds from 1000 up whose control schedule at λ = 2.2 to 4080 s has no 120 s planned rate ≥ 3.1; peaks 3.050, 3.050, 2.875, 3.058, 2.742). REG-19's configs and test with four changes: `--max-num-batched-tokens 8192`, `--num-gpu-blocks-override 6041`, `workload.rate` 2.2, and the seed (L1, 350 W, closed-loop turns; burst at 900 s for 180 s at 2.4 req/s of 2944-token prompts; arrivals to 4080 s; a 3000 s watch). Configs `configs/{burst,stage2_control}_l1pl350cl_r2.2_b8192_s<seed>.yaml`. |
| **Outcome rule** | `p8192.pair` per seed with REG-19's rules at λ = 2.2 (`gate.reg10_gate`, `p8192.cold_side`, `gate.reg19_seed_outcome`); matrix by `gate.reg19_outcome`: `surge_reading_wrong` if any control is `control_cold_no_surge`; `controls_not_healthy` if 2 or more bad controls; `too_few`; `supports` if k_clear ≥ 3; `supports_edge` if k ≥ 3; `some` if k = 1–2; `none` if k = 0. k of 5 with one-sided 95 % Clopper–Pearson bounds. Readout with a registered reading: `c_rel_floor` = (c − 1.931) / (2.2 − 1.931); a pass above 0.5 is named 'stuck by the verdict, but completing near λ'. |
| **Prediction** | Per seed: a control tips ≈ 0.05, another control failure ≈ 0.01, burst stuck through the watch without the line emptying ≈ 0.8, cold side ≈ 0.95, `pass_clear` ≈ 0.9 of passes. Outcome: `supports` 0.63, `surge_reading_wrong` 0.23, `supports_edge` 0.07, `some` 0.07, `none` < 0.01, `controls_not_healthy` < 0.01, computed on the stated assumption that one control tip ends the matrix as `surge_reading_wrong`. |
| **Decision under each outcome** | `supports`: the paper says that at 8192, at the same place in its window (λ = 2.2, 1.14 × that budget's cold floor), the burst left the engine stuck through a 3000 s watch beside a warm control in k of 5 calm-schedule seeds. `supports_edge`: the same, with the controls' waiting named. `some`, `none`: the headline is scoped to the default budget. `controls_not_healthy`, `surge_reading_wrong`: λ = 2.2 is not reliably warm at 8192 on these schedules; no claim either way; the author decides on λ = 2.1. A refusal or a stopped queue: no outcome; the author decides. |
| **Adversarial review** | Two rounds before registration: round 1 READY with fixes, three blocking items (P-1, the pair function re-implemented and untested; P-2, the prediction; P-3, an alternative stated backwards), fixed; round 2 READY with fixes, blocking N-1 (a test sentinel that could not flip a seed) and P-1's threshold list, fixed. Neither round caught the gap between the registered text and the code found after the runs (see corrections). |
| **Result** | No outcome label (the author's ruling). 3 of 5 calm-schedule seeds (1007, 1008, 1009, `pass_clear`) stuck through the 3000 s watch beside a warm control (one-sided 95 % bounds 0.189 to 0.924). Seed 1002: both runs `bad_baseline`, cold at 252 s (control) and 246 s (burst run), before the burst. Seed 1004: burst run `bad_baseline` (baseline percent fast 0.976 against 0.98). The registered functions return `supports` (k_clear 3 of 5); the registration's sentence gives `surge_reading_wrong`; neither is claimed. `c_rel_floor` −0.131 to −0.070 in the three passes. |
| **Prediction held** | not scored: no outcome was claimed; had a label been taken, `supports` had 0.63 (the likeliest) and `surge_reading_wrong` 0.23. Per seed, 1 of 5 controls tipped (before the burst) against P(≥ 1 of 5) ≈ 0.23; the three judged burst runs were stuck and `pass_clear`. |
| **Not separated** | Persistence by owed backlog rather than a cold cache is not separated. Whether seed 1002 was a cold start (tipped at ≈ 250 s while the cache was still filling) or the warm state ending is not checked. |
| **Corrections** | 2026-11-22: the registration said one control tip ends the matrix as `surge_reading_wrong`, but the registered code ranks `bad_baseline` first, so a control that tips inside its own baseline counts as one bad control; the two readings give different outcomes on these runs (`supports` against `surge_reading_wrong`), and the author ruled that only the counts are reported. 2026-11-22: the values 0.025, 0.007 and 0.976 called a 'completed share' are percent fast (requests ok within the TTFT SLO). |
| **In the paper** | Appendix A, 'the 8192 burst test'; §4.2 (P67); the 8192 row of Table 2 in §4 (P58). |
| **Notes** | Not claimed: that λ = 2.2 at 8192 is reliably warm on calm schedules (1 of 5 went cold unprompted), that P0 holds at 8192 by the registered matrix rule, anything about stormier schedules, or an unpinned pool (5850 blocks). The paper states the counts and never uses 'supports' for this test. |
