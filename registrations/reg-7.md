| | |
|---|---|
| **Question** | Feasibility gate for setup L1 (the 5 s-gap setup with a 2048-token system prompt): is there a load with c_b(λ) < λ ≤ c_warm(λ), a cold backlogged completion rate below λ while the warm server keeps up (`docs/model.md` M2)? Tests M2 as the precondition of C1, not C1. |
| **Runs** | At 420 W. G1: cache-on sweep, λ = 2, 3, 3.5, 4, 4.5, 5, 5.5, 6, 7, 900 s, seed 0, no dev mode. G2: cache-off sweep, λ = 1, 1.5, 2, 2.5, 3, 3.5, 4. G3 at λ_test: one control and one burst run, 2580 s, seed 1, burst at 900 s for 180 s at λ_test with 2944-token prompts. Budget ≤ 9 GPU h without reruns. |
| **Outcome rule** | μ_warm: highest rate passing throughput ≥ 0.95 × realized planned rate and waiting slope ≤ 0.01 req/s, monotone. μ_sat,off = `gate.cold_floor` (λ_sat the lowest λ with mean KV ≥ 0.85; every row above saturated; mean over ≥ 2 rows; statuses `ok`, `not_monotone`, `too_few`, `unsaturated`). λ_test = `gate.choose_lambda`: largest multiple of 0.5 that is ≤ 0.8 μ_warm and ≥ 1.3 μ_sat,off, stepped down until the G1 run at the smallest swept rate ≥ λ_test has pooled percent fast ≥ 0.98 at TTFT ≤ 1.0 s. G3 by `gate.gate_verdict`: a span ([600, 900), [900, 1200), [1200, 1500) s after 1080 s) holds if backlogged at every scrape, burst-free, cold (cached share ≤ baseline − 0.06) and its one-sided 99 % Poisson upper bound is below both λ_test and the span's λp; it counts if the control is not backlogged there. Labels: `inconclusive` (an `unclear` verdict, a `bad_baseline` burst run, an undefined span, or a `stuck` burst run with no counting span), `control_not_healthy`, `pass` (some span counts), `drains`. |
| **Prediction** | μ_sat,off ∈ [1.4, 2.2] (point 1.7), status `ok`; μ_off ∈ {1, 1.5, 2}; μ_warm ∈ [3, 6] (point 4.5). λ_test exists with p ≈ 0.7 (point 3.5). Given G3: `pass` ≈ 0.3, `drains` ≈ 0.45, `control_not_healthy` ≈ 0.1, `inconclusive` ≈ 0.15. Overall `pass` ≈ 0.2. |
| **Decision under each outcome** | No λ_test with floor `ok`: no shock matrix at L1, μ into M2, the author picks the next factor; with the floor unmeasured, a new registration extends or repeats G2. `pass`: the shock matrix at λ_test (registered first), then the confirmation run, the caching-off control and the loop figure. `drains`: record c_b and 1 − c_b / μ_warm in M2; if `gate.overlap_share` > 0.5 propose closed-loop turns, otherwise propose writing up the negative. `control_not_healthy`: one retry pair at λ_test − 0.5 if still ≥ 1.3 μ_sat,off. `inconclusive`: rerun the pair unchanged. |
| **Adversarial review** | One round of adversarial review. Main defect: a false `pass` on a draining server, because a span was compared with its own planned rate only; also an unjudged control tail, missing data read as `drains`, and grid and floor defects. All changes (c_upper below both λ_test and λp, a matched-span control, an `inconclusive` label, floor fixes, 0.5-step G1 with a monotone rule, `gate.slo_feasible`, a named overlap function, G3 config contents registered) were made before approval; one more change after approval and before the commit: a `stuck` burst run with no counting span is `inconclusive`, not `drains`. |
| **Result** | No result: the gate was not computed. G1 has one valid run per rate from 2 to 5.5 (λ = 4.5 to 5.5 after reruns); λ = 6 was heat-invalid in all three allowed runs and λ = 7 was not rerun. G2 has no valid run: λ = 1 was heat-invalid in all three allowed runs (SW-thermal 0.062, 0.097, 0.135), λ = 1.5 invalid and λ = 2 stopped. REG-8 superseded REG-7 at a 350 W power limit. |
| **Prediction held** | no result (gate not computed) |
