# D1: the session cap

*Registered 2026-11-15 · GPU runs · claim C2 · result 2026-11-16*

| | |
|---|---|
| **Question** | At λ = 2.0 (L1, 350 W, closed-loop turns), on the five seeds whose burst runs all ended `stuck` under REG-19, does the same burst leave the system cold and backlogged at the end of the 3000 s watch when the sessions in service are capped at the highest number the same seed's no-burst control had in service at once? |
| **Runs** | Five capped burst runs, seeds 15–19, each REG-19's burst config with only `workload.sessions.cap` added; the caps (29, 25, 29, 26, 25) were computed first on REG-19's five controls by `d1.cap_values`. ≈ 6.2 GPU h. |
| **Outcome rule** | `d1.label` per run on the reuse of later turns, the server's line and the cap's queue (baseline [300, 900) s, end window [3480, 4080) s, thresholds 0.06 on reuse and 1.0 on queues): a warm server with the cap queue back within 1.0 session of its baseline is `recovered` (or `recovered_cap_draining`, else `server_only`); end reuse ≤ baseline − 0.06 with the cap's queue backlogged is `stuck`, without it `partial`; also `rewarming`, `bad_baseline`, `unclear`. `d1.outcome`, in order: `too_few` (n < 3); `refutes` (`stuck` ≥ 3); `supports` (no seed stuck and cut ≥ 3); `admission_only` (`server_only` ≥ 3); `mixed` otherwise. |
| **Prediction** | Per valid seed P(cut) ≈ 0.76, P(stuck under the cap) ≈ 0.04; matrix P(`supports`) 0.7628, P(`mixed`) 0.2364, P(`refutes`) 0.0006, P(`admission_only`) 0.0003, P(`too_few`) 0; caps 23–31, median ≈ 26; a cut seed's onset class `burst_only` 0.60, `formed_then_cleared` 0.25 (BELIEF). |
| **Decision under each outcome** | `supports`: C2's status may say the cap prevented the stuck state, split by onset class, with the confounds in the same sentence, and no further C2 run follows; `refutes`: C2's status changes the other way and loop-cut runs stop until the author decides; `mixed`: no change, and the author chooses between more seeds and reporting D1 as inconclusive; `admission_only`: the cause is found before anything is drafted. |
| **Adversarial review** | Two rounds: round 1 NOT READY with eleven required changes (DG1–DG11), applied with three argued departures; round 2 READY provided DJ1–DJ3, applied. Later changes (one `stuck` label, D1 as a refutation test) were listed as unreviewed and approved by the author with that list in view. |
| **Result** | `supports`: 5 of 5 seeds cut (all `recovered`), none stuck; stuck 0 of 5 (upper bound 0.451), cut 5 of 5 (lower bound 0.549); McNemar's exact one-sided p 0.031 against REG-19's 5 of 5 stuck (a readout). Onset: 3 `formed_then_cleared`, 2 `burst_only`; no capped seed reached the stuck state's reuse or completion rate after the burst. |
| **Prediction held** | yes (likeliest outcome, 0.7628) |
| **Not separated** | The loop cut (C2) against a smaller effective shock; population-driven pool pressure with or without the prefix cache; which link (running batch, pool gauge, idle time) mattered; the harness change between REG-19 and D1. |
| **Corrections** | 2026-11-18: the registration filed Huang and Liu's session cap (0 of 10) as a rescue; it was prevention, so D1 replicates their preventive cap. No verdict changes. |
| **In the paper** | The session cap: §4.5 (P38), Table 2 (P58), Appendix C.14, Appendix D's table (P32). |
| **Notes** | D2 (caching off) was answered without a run. The cap is on from t = 0, so D1 tests prevention, not rescue. All five runs were valid on one attempt. |
